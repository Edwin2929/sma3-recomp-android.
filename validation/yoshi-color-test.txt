Yoshi Color / Android 0.10.8-beta — native qualification, 2026-10-29

Compiler: GCC 13.3.0, Linux x86_64.
This report covers host unit/rendering checks, not a measurement on a phone.
No original game ROM, BIOS or player save is needed for these public tests.

1. Selective palette + production PPU

PASS: 5 scenarios, 932845 checks; selective Yoshi color, 8 references,
software/hardware fades, real native/wide PPU, immutable memory, restore
and request epoch.

The five groups exercise:
- A closed scene list, verified scene owners, normal Yoshi only, all 16 OBJ
  palette banks and all 1024 starting tiles. Same-bank Baby Mario tiles,
  different banks, 8bpp and OBJ-window sprites are excluded.
- Six fixed custom color oracles, eight reference palettes, both directions
  of 32-step software fades, all 256 OBJ entries, exact input immutability,
  malformed references, unsupported palettes, cache hits and invalidation.
- The real compositor at 240x160 and 356x160. Exactly 24 body pixels change
  in the synthetic scene; all other pixels, white belly, shoes, same-bank
  Mario-shaped fixture, background and equal-color unrelated sprites remain
  as before. The live scanline and full-frame paths agree for affine OBJ.
- 256 combinations of viewport width, mod enable, normal/semi-transparent
  OBJ, first/second target selection, window effects and four BLDCNT modes;
  also EVY zero/clamping and a disabled second-target BG.
- Atomic configuration publication and epoch invalidation, including invalid
  RGB input, repeated identical requests, disabled drafts and a missing bus.

Reproduction from the repository root (patched ../gbarecomp):

  c++ -std=c++20 -O2 -I src -I ../gbarecomp/src/armv4t \
    -I ../gbarecomp/external/arm-recomp-core/profiles/armv4t_gba \
    -I ../gbarecomp/src/gba -I ../gbarecomp/src/runtime \
    -I ../gbarecomp/src/debug validation/yoshi_color_test.cpp \
    src/yoshi_color.cpp ../gbarecomp/src/gba/gba_ppu.cpp \
    -o /tmp/sma3-yoshi-color-test
  /tmp/sma3-yoshi-color-test

2. Sanitizers

PASS: the same 5 scenarios / 932845 checks with AddressSanitizer and
UndefinedBehaviorSanitizer. Flags replace -O2 above with:

  -O1 -g -fsanitize=address,undefined -fno-sanitize=vptr \
    -fno-omit-frame-pointer

Run with ASAN_OPTIONS=detect_leaks=0. Virtual-table checks are excluded
because this isolated fixture stubs active_bus() as null and does not link
the polymorphic GbaBus implementation/typeinfo. LeakSanitizer is not covered
in this restricted process-inspection environment. No ASan/UBSan runtime
diagnostics were reported.

3. Independently reproducible pre-existing OBJ effect bug

With only the palette hook (patch 15), the same test failed:
  FAIL: full hardware fade remains black
  exit code: 1

That PPU source SHA256 was:
  2746fa26ed728e53e519dc2679d9b58aa353cf768f6712490c8bfe93c2b353b0

Normal OBJ ignored BLDCNT's first-target selection. Patch 16 separates
ordinary selection from forced semi-transparent alpha in the existing
one-byte field. Brightness no longer forces alpha on normal OBJ; forced
alpha takes priority when an eligible lower target is present. The color
mod can be disabled and the corrected hardware selection still applies.
